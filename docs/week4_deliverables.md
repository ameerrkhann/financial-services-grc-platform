## 1. Demo dataset — `src/database/grc_platform.db`

**Produced by:** `src/database/seed_demo_data.py`
**Gitignored.** The database is disposable; the seed script is the source of truth.

Rebuilds the whole dataset in one command:

- One NIST CSF 2.0 assessment for First National Bank (Fictional), assessor Ameer Khan — Govern 2, Identify 2, Protect 3, Detect 2, Respond 1, Recover 3, each with a written rationale, against a target maturity of 4 per function.
- Control gaps generated by calling `scoring_engine.generate_gaps()`, so the seeded gaps and their framework references are identical to those an interactive assessment produces. There is no duplicate gap map.
- All five FAIR scenarios run at their fixed per-scenario seeds (`fair_engine.seed_for`), with ALE, percentiles, residual ALE and ROSI stored.
- Eight fictional vendors across all five service types, scored through `vendor_risk.scoring.calculate_score` — the same function the Streamlit app calls.

**Two design choices worth knowing:**

Vendors are described by a security posture — a default answer plus overrides per question category and per individual question — rather than a hand-written answer sheet. That reads like a real finding ("Partial across Governance and Business Continuity, No on breach notification and bias testing") and keeps the profiles short.

Each vendor's `expected_tier` is asserted after scoring. If a question weight or tier threshold ever changes, the seed raises with the actual versus expected tier instead of quietly producing a demo with no Critical vendor.

Assessment dates are relative to `date.today()`, so the three deliberately overdue vendors stay overdue however long from now the script is run.

**Output:** 1 assessment, 6 function scores, 4 control gaps, 5 risk scenarios, 8 vendor assessments and their individual question responses.

## 2. Loss exceedance curves — `dashboards/lec_all_scenarios.png` (+ 5 per-scenario)

**Produced by:** `src/risk_quantification/loss_exceedance.py`

For each scenario, the probability that annual loss exceeds any given dollar
amount, with ALE, 90th and 95th percentile reference lines. Dark theme
(`#0f0f0f` figure, `#1a1a1a` plot area) so the chart set reads as one system.

Uses the same `seed_for()` seeds as `run_scenarios.py`, so the curve and the
stored ALE come from the identical simulation.

## 3. NIST CSF maturity radar — `dashboards/csf_radar.png`

**Produced by:** `src/compliance/csf_radar.py`

Current versus target maturity across all six CSF 2.0 functions. Current is a
filled cyan polygon, target a dashed yellow hexagon at 4, with an annotation
box carrying the overall score, the average gap, and how many functions sit
below the defined level. Scores are read from the database rather than
hardcoded, so the chart tracks whatever the last assessment wrote.

The weakest function is direct-labelled and the target series is dashed, so the
two series stay distinguishable without relying on colour alone. The cyan and
yellow pair clears colour-vision-deficiency separation comfortably (ΔE 25.5
protan, 20.9 tritan, validated rather than eyeballed), but the chart should not
depend on that.

Power BI web may block the AppSource radar visual on a university tenant, so
this matplotlib version is the reliable one for the README and for LinkedIn.

## 4. Power BI data export — `dashboards/grc_powerbi_data.xlsx`

**Produced by:** `src/reporting/export_for_powerbi.py`

Seven sheets, each formatted as a named Excel table so Power BI binds to it
cleanly.

| Sheet | Table name | Rows | Contents |
|-------|-----------|------|----------|
| RiskScenarios | `RiskScenarios_tbl` | 5 | ALE, percentiles, control cost, effectiveness, residual ALE, ROSI, likelihood and impact bands |
| LossExceedance | `LossExceedance_tbl` | 500 | 100 curve points per scenario |
| CSFScores | `CSFScores_tbl` | 6 | Current score, `target_score`, `gap_to_target`, rationale |
| ControlGaps | `ControlGaps_tbl` | 4 | Gap, priority, NIST / ISO / SOC 2 references |
| VendorAssessments | `VendorAssessments_tbl` | 8 | Score, tier, gaps, plus `reassessment_window_days`, `days_since_assessment`, `reassessment_due`, `is_overdue` |
| VendorTierSummary | `VendorTierSummary_tbl` | 4 | Vendor count per tier |
| KPISummary | `KPISummary_tbl` | 1 | The eight headline figures |

> **Do not rename a sheet or a `<Sheet>_tbl` table.** The published Power BI
> report binds to these names. Adding columns is safe; renaming or removing
> breaks the live report.

`reassessment_due` is derived from the same per-tier window
(`RISK_TIERS[...]["reassessment_days"]`) that `get_overdue_vendors()` enforces,
so the dashboard and the database cannot disagree about who is overdue.

### `compliance_posture_score`

The one figure in the export that is not a direct measurement:

```
compliance_posture_score = 0.5 × avg_vendor_score
                         + 0.5 × (csf_overall_score / 5 × 100)
```

Half the average vendor questionnaire score (already 0–100) and half the NIST
CSF overall maturity rescaled from /5 to /100. It exists to trend one number
over time on a dashboard tile. **No framework defines it** — it is a
presentation metric, documented as such in the function docstring, and should
be described that way rather than defended as a standard.

Current value: **53.8**, from an average vendor score of 64.2 and CSF maturity
of 2.17.

## 5. Executive briefing — `docs/executive_summary.pdf`

**Produced by:** `src/reporting/executive_summary.py` (reportlab)

Three pages, written to the CISO of First National Bank (Fictional). Every
figure is read from the database — there are no hardcoded numbers in the
generator.

| Section | Contents |
|---------|----------|
| Header | Title, byline, assessment and issue dates, and a simulated-data disclaimer in a boxed callout |
| Executive Overview | Three short paragraphs leading with the $19.58M portfolio ALE |
| Key Risk Findings | Five scenarios with ALE, 90th percentile, control cost, residual ALE and ROSI, plus a portfolio total row; embeds `lec_all_scenarios.png` |
| NIST CSF Maturity | Overall score, per-function current versus target table; embeds `csf_radar.png` |
| Top Three Recommendations | Derived from the data, not a fixed list |
| OSFI Alignment | B-13, B-10, E-21 and the incident reporting advisory, using the corrected references |
| Vendor Risk Snapshot | Tier counts with reassessment cycles, and the three overdue vendors |

**The recommendations are derived.** Recommendation 1 is whichever scenario
carries the highest ALE. Recommendation 2 is whichever CSF function scores
lowest; because a maturity gap has no control cost of its own, its expected
effect is computed as the combined ALE of the scenarios that cite that
function's control ID — `RS.MA-01` is cited by 2 of 5 scenarios carrying
$6.99M. Recommendation 3 is driven by the Critical-tier and overdue vendors,
priced against the third-party scenario's own control set.

Design: one accent colour (`#14607A`), 10.5pt body, no walls of text. The pages
were rendered to images and reviewed before the file was called finished, which
is how four layout defects were caught — two near-empty pages, an orphaned
heading, a recommendation table split across a page break, and a wrapping
column header.

## 6. Risk register — `templates/risk_register.xlsx`

**Produced by:** `src/reporting/build_templates.py` (openpyxl)

Twenty columns, from Risk ID through to the NIST CSF and OSFI references.

**Live formulas**, present in the blank rows as well as the filled ones, so a
new entry scores itself as soon as likelihood and impact are typed:

| Column | Formula |
|--------|---------|
| Inherent Risk | `Likelihood × Impact` (1–25) |
| Inherent Rating | ≥15 Critical, ≥10 High, ≥5 Medium, else Low |
| Residual Risk | `Inherent Risk × (1 − Control Effectiveness)` |
| Residual Rating | Same thresholds, applied to Residual Risk |

**Also included:** whole-number 1–5 limits on Likelihood and Impact, a 0–100%
limit on Control Effectiveness, dropdowns on Treatment
(Accept / Mitigate / Transfer / Avoid) and Status, conditional formatting on
both rating columns, a frozen header row, an autofilter, five worked example
rows — one per FAIR scenario, with ALE read from the database — twenty blank
formatted rows, and an Instructions sheet documenting every column plus the
escalation scale.

> **A note the Instructions sheet also carries:** a 60–80% effectiveness
> assumption pulls almost any inherent score below 5, so every example row
> rates Low residual. If that looks too comfortable, the effectiveness
> assumption is the number to challenge, not the formula.

## 7. Control matrix — `templates/control_matrix.xlsx`

**Produced by:** `src/reporting/build_templates.py` (openpyxl)

One row per control in `framework_mapper.CONTROL_MAPPING` — 17 controls, each
mapped across NIST CSF 2.0, ISO/IEC 27001:2022, SOC 2 and the OSFI guideline it
supports, with a control owner, test frequency, last tested date, test result
and an evidence link column.

Test Result is a dropdown (Effective / Partially Effective / Ineffective / Not
Tested) with conditional formatting. Results are **seeded from each function's
CSF maturity score** rather than invented — a function scoring 3 or above has
its controls recorded as tested and effective, a 2 is partially effective, a 1
has nothing to test yet — so the matrix and the assessment cannot contradict
each other.

The Summary sheet counts controls per function and per test result using
`COUNTIF` and `COUNTIFS` against the matrix sheet, plus a coverage breakdown
with percentages. Change a result on the matrix and the summary follows.

## 8. Test suite and CI

**Produced by:** `pytest` / `.github/workflows/tests.yml`

85 tests across four files. `tests/conftest.py` sets `GRC_DB_PATH` to a fresh
temporary file for every single test via an autouse fixture, so no test can
reach the real database even by accident.

| File | What it pins down |
|------|-------------------|
| `test_fair_engine.py` | Simulated ALE within 3% of the analytic mean `λ · exp(μ + σ²/2)` for every scenario, percentile ordering, zero-frequency edge case, seed reproducibility, and the ROSI formula |
| `test_vendor_scoring.py` | All-Yes = 100/Low and all-No = 0/Critical for every service type, N/A excluded from the denominator, tier boundaries at 40/41, 60/61 and 80/81 |
| `test_gap_analysis.py` | Only scores below 3 produce gaps, roadmap ordering by risk score, and no retired CSF 1.1 or ISO 2013 references |
| `test_db_manager.py` | Round-trip insert and read on a temporary database, per-tier overdue windows, stale-schema migration |

Two tests exist specifically to stop known bugs returning:
`test_losses_are_summed_not_multiplied()` compares the summed and
multiplicative FAIR models on identical inputs, and the reference-integrity
tests fail if `PR.AC-`, `RS.RP-`, `RC.IM-` or the ISO 2013 clause numbers
reappear.

CI runs pytest on Python 3.13 on ubuntu-latest, then rebuilds the demo dataset
and every deliverable above — so it proves the pipeline still runs end to end,
not merely that the units pass.
